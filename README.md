# Personal AI Workflow Hub

Минимальный старт проекта: Telegram бот принимает сообщение через FastAPI webhook и отвечает обратно в Telegram.

## 1. Создать виртуальное окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
```

## 2. Установить зависимости

```bash
pip install -r requirements.txt
```

## 3. Создать `.env`

Скопируй `.env.example` в `.env` и вставь свои ключи:

```bash
cp .env.example .env
```

Минимально нужен:

```env
TELEGRAM_BOT_TOKEN=твой_токен_от_BotFather
OPENAI_API_KEY=твой_openai_api_key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_AUDIO_MODEL=whisper-1
```

## 4. Запустить backend

```bash
uvicorn app.main:app --reload
```

Локальный сервер будет доступен тут:

```text
http://127.0.0.1:8000
```

## 5. Проверить здоровье сервера

Открой:

```text
http://127.0.0.1:8000/health
```

Должен вернуться ответ:

```json
{"status":"ok"}
```

## 6. Подключить Telegram webhook

Telegram не сможет отправить сообщение на локальный адрес `127.0.0.1`, поэтому нужен публичный HTTPS URL.

Для локальной разработки можно использовать:

- ngrok
- Cloudflare Tunnel
- локальный деплой на Render / Railway / Fly.io

### Вариант с ngrok

1. Установи ngrok и войди в аккаунт на сайте ngrok.
2. Скопируй authtoken из раздела `Your Authtoken`.
3. Подключи authtoken:

```bash
ngrok config add-authtoken твой_ngrok_authtoken
```

4. Запусти backend:

```bash
uvicorn app.main:app --reload
```

5. В другом терминале запусти туннель:

```bash
ngrok http 8000
```

6. Скопируй HTTPS URL из строки `Forwarding`, например:

```text
https://abc123.ngrok-free.app
```

Когда публичный URL готов, добавь его в `.env`:

```env
APP_URL=https://your-public-url.example.com
```

Потом запусти:

```bash
python scripts/set_webhook.py
```

Если нужно отключить webhook:

```bash
python scripts/delete_webhook.py
```

## Что Уже Есть

- `POST /telegram/webhook` принимает события от Telegram.
- Если пришел текст, бот отправляет его на AI-анализ.
- Если пришло голосовое сообщение, бот распознает речь и обрабатывает ее как обычный текст.
- Для текста используется `OPENAI_MODEL`, для голосовых сначала используется `OPENAI_AUDIO_MODEL`, а потом распознанный текст идет в обычный текстовый pipeline.
- Если задача назначена `planner_agent`, бот сразу составляет структурированный план: цель, допущения, этапы, материалы, риски, вопросы и первый шаг.
- Supervisor Agent проверяет входящую задачу перед сохранением: повышает приоритет по срочным словам, относит задачи к недельному плану и направляет важные задачи в Planner Agent.
- Каждая обработанная задача сохраняется в локальную SQLite базу `workflow.db`.
- Бот автоматически связывает задачи с проектом, если AI-разбор понимает направление работы.
- Команда `/задачи` показывает последние сохраненные задачи.
- Команда `/сегодня` показывает фокус на сегодня: задачи на сегодня, high-priority задачи и недельные задачи без точной даты.
- Команда `/tomorrow` или `/завтра` показывает задачи на завтра.
- Команда `/week` или `/неделя` показывает задачи на неделю без точной даты.
- Команда `/active` или `/активные` показывает все активные задачи.
- Фразы вроде `план на завтра` и `задачи на завтра` теперь показывают завтрашние задачи, а не создают новую задачу.
- Фразы вроде `план на неделю` и `задачи на неделю` теперь показывают недельные задачи, а не создают новую задачу.
- Команда `/projects` или `/проекты` показывает текущие проекты и количество задач в них.
- Команда `/project 1` или `/проект 1` открывает конкретный проект и показывает его задачи.
- Команда `/plan 1` или `/план 1` строит или обновляет Planner-план для уже сохраненной задачи.
- Команда `/subtasks 1` или `/подзадачи 1` показывает подзадачи внутри большой задачи.
- Команда `/subdone 1` или `/подготово 1` закрывает подзадачу.
- Кнопка `Шаги #...` открывает подзадачи прямо из списка задач.
- Если все подзадачи закрыты, основная задача закрывается автоматически.
- Команда `/sync_notion` или `/ноушен` синхронизирует задачи с Notion, если Notion настроен в `.env`.
- Команда `/sync_from_notion` или `/из_ноушен` забирает статусы из Notion обратно в бота.
- Команда `/brief` или `/бриф` отправляет утренний бриф вручную.
- Команда `/retro` или `/ретро` запускает вечернюю ретроспективу вручную.
- Команда `/memory` или `/память` показывает последние записи долговременной памяти агента.
- Команда `/deadline 7 2026-06-15` или `/срок 7 2026-06-15` ставит срок конкретной задаче.
- Команда `/готово 1` закрывает задачу с номером 1.
- Команда `/done 1 120` или `/готово 1 120` закрывает задачу и сохраняет фактическое время выполнения в минутах.
- Команда `/отмена 1` отменяет задачу с номером 1.
- Команда `/статус` проверяет backend.
- Под списком задач есть кнопки выбора номера: `Готово #...`, `Отмена #...`, `План #...` и `Шаги #...`.
- Боковое меню Telegram использует английские команды с русскими описаниями, потому что Telegram Bot API разрешает в названиях команд только lowercase English letters, digits и underscores.
- Planner Agent получает контекст из `WORKFLOW_CONTEXT.md` и последних задач в SQLite, чтобы строить планы с учетом текущего workflow.
- Planner Agent сохраняет шаги плана как подзадачи внутри основной задачи.
- При создании задачи AI оценивает длительность в минутах и сохраняет ее в `estimated_minutes`.
- При закрытии задачи с фактическим временем бот сохраняет `actual_minutes` и считает `time_estimation_accuracy`.
- High-priority слова: `важно`, `очень важно`, `экстренно`, `срочно`, `как можно быстрее`, `чем раньше тем лучше`, `критично`, `горит`, `немедленно`.
- Если бот понимает, что пользователь хочет изменить существующую задачу, но не уверен какую, он задает уточняющий вопрос и показывает активные задачи вместо создания новой.
- Если пришло что-то другое, бот просит отправить текст.

## Контекст Для Planner Agent

Файл `WORKFLOW_CONTEXT.md` хранит рабочий контекст для планировщика: роль системы, правила планирования и текущие направления.

Когда приходит задача для `planner_agent`, бот дополнительно передает в модель:

- содержимое `WORKFLOW_CONTEXT.md`;
- активные и недавние задачи из `workflow.db`.
- текущие проекты и количество задач в каждом проекте.

Если нужно изменить стиль планов или добавить текущие проекты, отредактируй `WORKFLOW_CONTEXT.md`.

## Notion Sync

Бот может синхронизировать задачи в Notion-доску.

В `.env` нужны:

```env
NOTION_TOKEN=твой_notion_integration_token
NOTION_TASKS_DATA_SOURCE_ID=id_data_source_твоей_доски
NOTION_VERSION=2026-03-11
```

Рекомендуемые колонки в Notion:

- `Name` — Title
- `Status` — Select: `In Progress`, `Done`, `Cancelled`
- `Priority` — Select: `high`, `medium`, `low`
- `Due` — Date
- `Project` — Text
- `Period` — Select: `week`
- `Agent` — Select
- `Type` — Select
- `Local ID` — Number

После настройки запусти `/sync_notion`.

## Утренний Бриф

APScheduler запускается вместе с FastAPI backend и каждый день отправляет утренний бриф.

Настройки по умолчанию:

```env
MORNING_BRIEF_ENABLED=true
MORNING_BRIEF_TIMEZONE=Asia/Almaty
MORNING_BRIEF_HOUR=10
MORNING_BRIEF_MINUTE=0
```

Бриф собирает:

- задачи на сегодня;
- high-priority задачи;
- недельные задачи;
- открытые подзадачи.

В Telegram бриф приходит с кнопками:

- `✅ Принять план`
- `📝 Изменить`
- `⏰ Отложить напоминание`

Проверить вручную можно командой `/brief`.

## Вечерняя Ретроспектива

APScheduler каждый вечер спрашивает, как прошел день, чтобы Planner Agent точнее оценивал время и порядок задач.

Настройки по умолчанию:

```env
EVENING_RETRO_ENABLED=true
EVENING_RETRO_TIMEZONE=Asia/Almaty
EVENING_RETRO_HOUR=21
EVENING_RETRO_MINUTE=0
```

Ретроспектива спрашивает:

- что сделано;
- что не сделано;
- что пошло не так;
- где оценка времени была неверной.

Ответ сохраняется в SQLite в таблицу `daily_retrospectives`, AI делает краткий разбор, а последние ретроспективы передаются в Planner Agent и утренний бриф как контекст.

Проверить вручную можно командой `/retro`.

## Долговременная Память Агентов

Бот использует ChromaDB как локальную векторную память. Это нужно, чтобы Planner Agent видел не только последние задачи, но и релевантные уроки из прошлого:

- какие планы уже предлагались;
- какие ретроспективы показали неверные оценки времени;
- что обычно мешает задачам;
- какие правила планирования стоит повторно учитывать.

Настройки:

```env
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
AGENT_MEMORY_ENABLED=true
AGENT_MEMORY_BACKEND=chromadb
AGENT_MEMORY_PATH=.chroma
AGENT_MEMORY_COLLECTION=agent_memory
```

Память пополняется автоматически:

- после Planner-планов;
- после вечерних ретроспектив.

Planner Agent и утренний бриф делают semantic search по ChromaDB и получают только релевантные воспоминания под текущий контекст.

Проверить память можно командой `/memory`.

Проиндексировать уже существующие Planner-планы и ретроспективы:

```bash
python scripts/index_agent_memory.py
```

Обратная синхронизация:

- если в Notion поставить `Status = Done`, команда `/sync_from_notion` закроет задачу в боте;
- если поставить `Status = Cancelled`, команда `/sync_from_notion` отменит задачу в боте;
- если страницу задачи удалить или отправить в архив/корзину, команда `/sync_from_notion` пометит задачу как `cancelled` локально.
